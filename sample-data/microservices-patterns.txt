Microservices architecture decomposes applications into small, independently deployable services, each owning its data and business logic. Services communicate via REST APIs, message queues (RabbitMQ, Kafka), or gRPC. Benefits include independent scaling, technology heterogeneity (each service can use different languages), and fault isolation. Challenges include distributed system complexity, data consistency across services, network latency, and operational overhead. Common patterns: API Gateway (single entry point), Circuit Breaker (prevents cascade failures), Saga (distributed transactions), Event Sourcing (storing state changes as events), and CQRS (separating read and write models). Service mesh tools like Istio handle cross-cutting concerns such as mutual TLS, observability, and traffic management. Conway's Law suggests that system architecture mirrors organizational communication structures.
