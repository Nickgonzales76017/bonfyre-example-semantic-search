WebSockets enable full-duplex, real-time communication between client and server over a single persistent TCP connection. Unlike HTTP's request-response model, either side can send messages at any time after the initial handshake. The connection starts as an HTTP upgrade request with specific headers (Upgrade: websocket, Connection: Upgrade). Common use cases include chat applications, live notifications, collaborative editing, real-time dashboards, multiplayer games, and live sports scores. Server-Sent Events (SSE) is a simpler alternative when only server-to-client streaming is needed. Socket.IO is a popular library that adds automatic reconnection, room-based broadcasting, and fallback to HTTP long-polling. Scaling WebSockets requires sticky sessions or a pub/sub layer (Redis) to route messages across multiple server instances. The ws:// protocol uses port 80, while wss:// (encrypted) uses port 443.
