SQL query optimization starts with understanding how the database executes queries. EXPLAIN shows the query plan; EXPLAIN ANALYZE adds actual execution times. Common optimizations include adding indexes on WHERE, JOIN, and ORDER BY columns, avoiding SELECT * (fetch only needed columns), using LIMIT for pagination, and replacing correlated subqueries with JOINs. Index-only scans are the fastest because data is read entirely from the index without touching the table. Query planners use statistics to estimate cardinality and choose between nested loop, hash, and merge join strategies. Partitioning large tables by range or hash reduces the data scanned per query. Connection pooling (PgBouncer, HikariCP) reduces overhead from establishing new connections. Materialized views precompute expensive queries. N+1 query problems occur when ORM code triggers one query per row instead of batching.
