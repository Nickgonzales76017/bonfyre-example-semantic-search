Database indexing dramatically improves query performance by creating data structures that allow the database engine to find rows without scanning every table row. B-tree indexes are the most common, organizing data in a balanced tree structure with O(log n) lookup time. Hash indexes provide O(1) lookups for equality comparisons but don't support range queries. Composite indexes cover multiple columns and follow the leftmost prefix rule. The query optimizer uses statistics about data distribution to decide whether to use an index or fall back to a sequential scan. Over-indexing wastes storage and slows writes because every INSERT, UPDATE, and DELETE must also update all relevant indexes. EXPLAIN ANALYZE reveals the actual execution plan, showing whether indexes are being used and where bottlenecks exist.
