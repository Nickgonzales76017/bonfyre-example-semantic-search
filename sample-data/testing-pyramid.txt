The testing pyramid guides how many tests to write at each level: many unit tests at the base, fewer integration tests in the middle, and a small number of end-to-end tests at the top. Unit tests verify individual functions or methods in isolation, using mocks and stubs to remove external dependencies. They should be fast (milliseconds), deterministic, and test one behavior each. Integration tests verify that components work together correctly — database queries, API endpoints, message queue consumers. End-to-end tests simulate real user workflows through the entire system. Test-driven development (TDD) writes tests before implementation in a red-green-refactor cycle. Code coverage measures the percentage of code exercised by tests, but 100% coverage doesn't guarantee correctness. Property-based testing generates random inputs to find edge cases that handwritten tests miss. Mutation testing injects bugs to verify that tests detect them.
