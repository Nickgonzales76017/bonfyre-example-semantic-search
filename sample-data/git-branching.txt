Git branching enables parallel development by creating isolated lines of work. The main branch holds production-ready code. Feature branches diverge from main for new work and merge back via pull requests. Git Flow uses develop, feature, release, and hotfix branches for structured releases. GitHub Flow simplifies this to main + feature branches with continuous deployment. Trunk-based development keeps branches short-lived (hours, not weeks) to minimize merge conflicts. Key commands: git branch (list/create), git checkout -b (create and switch), git merge (combine branches), git rebase (replay commits on a new base), and git cherry-pick (apply specific commits). Merge strategies include fast-forward (linear history), recursive (three-way merge), and squash (condense feature commits into one). Good practices: descriptive branch names, small focused commits, rebasing before merging to maintain clean history.
